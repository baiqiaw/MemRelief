- `tests/MemRelief.Bench/`：验证台 console 工程（net10.0，Release/Debug 双配置可用）。
  - `BenchRunner`：四步链编排（TakeSnapshot→CandidateIds→CollectSignatures→Classify）+ 四段独立秒表；依赖接口注入（IScanner/IRulesEngine）可替身测试。

- `MemRelief.sln`：注册上述两工程。

## 关键裁决（自裁，报告已注明）

1. **工程形态**：`tests/MemRelief.Bench/`——同 TestProcs 定位（真机验收复用工具，独立工程，不进 T-19 单文件发布）。spec 未预定义验证台形态，按仓库惯例自定（任务授权项）。
2. **候选预筛口径**：spec §7 分解只有采集/验签/判定三段，CandidateIds（判定域纯函数）无独立预算——耗时单列展示、并入判定段预算对照，计入引擎合计（合计=四段全和，无遗漏）。报告注明口径。
3. **--repeat 多轮测量**：SignatureCache 随 Scanner 实例存活（scanner.md §6），轮 2 起缓存热与 App 常驻复扫同构。预算对照以缓存热轮为准，冷缓存首扫如实并报（见实测数据）。
4. **多轮输出**：轮 1 完整报告，轮 2 起仅计时表（明细各轮高度重复）。

## 真机实测（2026-09-13，主机 CGH，Release 配置）

- 构造进程：200 个 TestProcs 孤儿（`--mem-mb 1`，一次性 SpawnDriver 驱动，见"探查产物"）。目标 300–600 因 commit 余量不足收窄：200 孤儿后 commit 38.74/41.59 GB（单孤儿 ~32 MB），余量 2.65 GB 不支持加量——按任务授权"按本机实 capability 调整"取 200，报告注明。
- 快照总量 642（冷轮）/645（热轮）= 200 构造 + 系统自然 ~442。
- 冷缓存轮：采集 657ms ✓ / 验签 7203ms ✗ / 判定 39ms ✓ / 引擎合计 7900ms ✗。
- 热缓存轮：采集 378ms ✓ / 验签 3ms ✓ / 判定 1ms ✓ / **引擎合计 382ms ✓（≤2800ms）**。
- 冷热差异根因：SignatureCache 冷缓存 205 候选全量 WinVerifyTrust（~35ms/文件）；热轮全命中缓存。预算达标形态 = 缓存热复扫（产品常驻形态）；冷首扫超标是否豁免/验签并行化归 TL 裁决。
- 推荐准确性：存活 200 孤儿 ∩ 推荐明细 = 200/200（机器核对，零遗漏）；推荐 205 = 200 构造 + 5 自然项（crashpad×2/dotnet/TGitCache/VBCSCompiler，与基线采样 [3] 段判定同向）。

## 对抗性自测

- 空快照/零进程：替身返回空 ScanResult 真实触发渲染与编排（单测 `空快照_零进程_正常产出不抛`/`空快照渲染不抛且显示零进程`）；真机零进程不可构造，以替身承载。
- 计时异常：负值段/负总耗时/总耗时小于引擎合计三路径单测真实触发防御（`TimingAnomalies`）；真机 QPC 单调无法构造回退，防御层为逻辑兜底。实测两轮"计时异常: 无"。
- 测试进程清理：`taskkill /F /IM MemRelief.TestProcs.exe` 后 tasklist 确认残留 0。
- 单个 child 故障不击穿：SpawnDriver 逐个 try/catch（实测探查期 10 个参数错误 child 全数快速失败，其余正常）。
