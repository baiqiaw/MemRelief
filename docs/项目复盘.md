## 2. 可复用的经验（v2 与后续项目直接沿用）

1. **契约冻结 + issue 口径 + 账本双源**的编排三件套让多会话并行无冲突：任务状态只认 issue state + git 实证，账本只做索引，全程无双源打架。
2. **真机验收三件套**（TestProcs 构造器 + Bench 验证台 + UIA/量化脚本）把"真机验收"从纯手工变成可自动化采证：600 进程构造、整批释放计时、工作集峰值全部脚本化，验收人只做视觉/权限类确认。
3. **GWT 先行**：R01 的 13 条 GWT 在 T-06 阶段就落成 `ClassifyGwtTests.Gwt1-13`（合成数据一一对应），验收时"执行记录=测试名"，矩阵翻牌零争议。
4. **裁决留痕机制**（decisions-log + issue 评论 + PRD 变更记录三处同记）在多轮迭代中经受住了考验：工作集指标修订、集群豁免三态分治均可完整回溯。

## 3. 踩坑与教训（每条对应一个实测事故）

1. **机械信号无法判别"无窗口活工作进程"与"死残留"**（#46 三轮迭代）：claude.exe（正在干活的 AI 会话）和死会话的 node 链在窗口/连接/CPU 信号上几乎同形。教训：**杀错代价 >> 漏报代价**，保护名单是兜底防线；锚定守卫（直系祖先有可见窗口）是 v1.5 的可行折中，兄弟集群误推荐仍为已知边界（#51）。
2. **PRD 指标要带"适用前提"**：工作集 ≤100MB 是 .NET 8 时代参考值，运行时升 .NET 10 后实测 4 倍超标。PRD 预埋的"待 net10 基线回填+超标先归因"路径走通了，但若没有那句预埋就会变成需求事故。教训：**量化指标必须标注测量前提与失效处置路径**。
3. **文档-实现双源漂移**：集群豁免语义迭代时 PRD 文本两次滞后于代码，均被评审 S1 命中。教训：**改判定语义必须同提交同步 PRD 口径表**——"判定语义唯一事实源 = PRD F1 口径表"不是口号。
4. **真机集成测试的时序竞争**：`真机_执行前已退出_Exited`（#41）三次偶发，单跑必过、全量偶挂。教训：涉pid 复用/进程退出观测的测试需单跑隔离设计 + 已知 flaky 单独登记跟踪，不与回归混判。
5. **急切求值陷阱**：断言消息插值 `Assert.False(cond, $"{x.ExitCode}")` 在 cond=true 路径也会求值抛异常——本轮红灯阶段实际踩中。教训：**断言消息里的属性访问要放条件分支内**。
