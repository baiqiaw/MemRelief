## 第1层 · 决策层（Why & What）

### 1.1 需求本质
- **用户要完成的任务 / 要解决的问题**（一句话）：识别并安全结束占用内存的孤儿进程与无用应用，缓解慢性卡顿与偶发内存耗尽，且每个"杀/不杀"决策都有可读的理由。
- **不做的后果**：用户继续在任务管理器里凭进程名猜测哪些能杀——误杀系统进程导致重启、漏杀残留导致内存持续被占，90%+ 占用与卡顿/爆发长期存在。

### 1.2 证据（防伪需求，强制带来源）
- **用户原话**："我的电脑经常性内存使用90%以上，里面有大量的孤儿进程遗留，有大量我平时没用上的应用占着内存，我需要一个工具来清理并释放这些进程及所占内存；我需要的功能有：推荐可以释放的进程及内存，说明原因，主进程是谁等关键信息；不推荐的释放也需要说明，然后我可以多选进行一键释放；另外从网络搜索最佳实践。"（来源：2026-09-05 prd-writer 拷问会话原始输入，逐字引用；末句"从网络搜索最佳实践"界定为**开发期调研输入**——已执行，见下方调研结论与附录，产品自身不含联网功能）
- **体验确认**：内存 90%+ 时的实际体验为"慢性卡顿（切换慢/转圈）+ 偶发爆发（应用崩溃/提示内存不足）"混合（来源：拷问问题 1，用户选 D）。
- **最佳实践调研**（2026-09-05，链接见附录）：① 任务管理器占用率仅反映 In Use；standby/cache 属可回收缓存（计入"可用"而非"已使用"），不抬高占用率——高占用率不必然是问题，真压力信号是持续高占用+卡顿+commit 接近上限；② 传统内存优化器（EmptyWorkingSet 工作集修剪）被主流开发者共识视为无效（页面移入 standby 后软缺页弹回，还付性能代价），**真正释放内存的唯一有效手段是结束进程**；③ 孤儿进程检测以父 PID 存活判定为成熟方法；Windows 复用 PID，需以创建时间校正——父 PID 对应进程的创建时间**晚于**子进程时，恰证明真父已退出（存活者为 PID 复用者），应判孤儿。

### 1.3 业务目标与成功度量
- **业务目标**：从"经常性 90%+ 占用、慢性卡顿 + 偶发内存耗尽" → "一键清理后占用可观测下降、爆发频率下降、清理决策 10 秒内完成"。
- **成功度量（可验证）**：
  1. 每次一键释放报告并留痕**实际释放量（MB）**（R03/R06，日志可回溯）；
  2. 典型清理场景物理内存占用率下降幅度可由释放前后日志对比观测（不预设死数——下降量取决于当时进程构成）；
  3. 内存耗尽爆发（应用崩溃/提示内存不足）频率：v1 以用户主观体验 + R06 日志时间线回溯（无遥测，商用版升级）。

### 1.4 目标用户与场景
- **目标用户**：本人（Windows 11 x64，开发者）。v1 纯自用；架构上以分层设计为商用预留（见 §3.5）。
- **典型场景**：
  1. **日常清理**：感觉系统变卡 → 打开工具 → 扫描 → 读推荐与原因 → 勾选 → 一键释放（频率：每日~隔日）；
  2. **爆发应急**：应用提示内存不足/浏览器标签被杀 → 立即打开工具清理（频率：每周数次）；
  3. **来源体检**：查看哪些进程来自自启动/服务 → 自行到任务管理器禁用来源，治本（频率：每周）。
- **用户旅程**：感知卡顿/爆发（痛点：不知道哪些进程能杀）→ 打开工具扫描（痛点：任务管理器无推荐无解释）→ 读推荐+原因+进程树（解决：决策辅助）→ 多选勾选 → 一键释放 → 查看实际释放量验证（解决：效果可观测）。

### 1.5 范围与优先级
- **P0（必须做，= MVP 边界）**：扫描引擎与三级推荐（R01）、推荐列表信息展示（R02）、一键释放（R03）、白名单（R04）。
- **P1（辅助）**：内存概览条（R05）、释放历史日志（R06）。
- **不做（边界，v1 明确排除）**：
  - 自动/定时清理、托盘常驻——误杀风险与"用户自己决策"的诉求冲突（拷问问题 4）；
  - 自启动项禁用**操作**——写系统配置风险大，信息层展示已打通治本路径（拷问问题 5）；
  - 安装包/代码签名/自动更新/遥测/多语言——归 v2 商用化；
  - 自定义规则编辑器——v1 只留白名单，模式库随使用迭代（拷问问题 7）；
  - 工作集修剪类"内存优化"——调研证明无效（附录），不做。

## 第2层 · 方案层（How）

### 2.1 方案对比与选择
- **核心方案对比：怎么"释放内存"**
  - 方案 A：传统内存优化器（EmptyWorkingSet 修剪各进程工作集） | 优点：实现简单、数字立刻变好看 | 缺点：**无效**——页面移入 standby 后软缺页弹回，还付性能代价；开发者共识视之为安慰剂 | 成本：低
  - 方案 B：进程识别 + 结束进程（推荐引擎 + 树状两段式释放） | 优点：唯一真正释放内存的路径；契合"孤儿/无用应用"的实际病因 | 缺点：推荐准确性依赖规则工程质量 | 成本：中
  - **推荐**：B | **理由**：调研结论（附录）证明 A 类工具无效；用户的痛点构成（孤儿+无用应用）恰好是 B 的能力面。
- **技术栈对比**
  - 方案 A：Python + PySide6 + psutil | 优点：进程枚举开发最快、本机 Python 已装 | 缺点：PyInstaller 打包是杀软误报重灾区（系统工具被 AV 误杀 = 商用口碑灾难）；PySide6 LGPL 商用尽调问号；自身占用大 | 成本：开发低、商用迁移高
  - 方案 B：C# + WPF + .NET 8 + CsWin32 | 优点：单文件自包含发布、签名/安装包/自动更新生态成熟、WPF/.NET MIT 零授权歧义、原生占用小；本机 .NET SDK 8/9/10 已装（实测 2026-09-05） | 缺点：Win32 访问管道略多 | 成本：开发中、商用迁移零
  - **推荐**：B | **理由**：用户明确"为后续商用做准备"（拷问问题 9 追加前提）；商用最大成本在分发与信任面，正是 B 的长板；避免商用前整轮重写。
- **权限方案对比**：每次管理员启动（UAC 烦扰）vs **默认普通权限 + 按需"以管理员身份重启"**（推荐，主流做法）vs 单次碎片化提权（体验差）。推荐理由：主场景（用户级孤儿/残留）普通权限已覆盖。

### 2.2 实施计划与风险
- **里程碑**（个人项目，按序不拍日历）：
  - M1 扫描引擎核心：信号规则判定 + 三级分类，以命令行/测试先行验证推荐准确性（价值核心，先于界面）；
  - M2 GUI：三级列表 + 一键释放；
  - M3 收尾：白名单 + 概览 + 日志 + 自用打磨。

## 第3层 · 实现层（Detail）

### 适用性声明
> 【v2】声明下方条件性产物的适用性，供 prd_check #9 校验（v2 必填）。**异常处理表近普适、默认必备，不在本声明内**；仅状态流转/埋点按需求性质判定。

- 状态流转表：不适用（工具无实体生命周期/审批/订单流转；进程状态属操作系统域，工具只读判定，不持有状态机）
- 埋点方案：不适用（v1 纯本地自用无遥测，成功度量以 R06 本地日志与主观体验可观测；商用遥测归 v2，见 §1.5 不做边界）

### 3.1 功能详细设计（逐功能）
#### 功能 F1：扫描引擎与三级推荐（对应 R01）
- **触发**：主界面"开始扫描"按钮；普通权限即可（提权项见 F3）。
- **输入**：无参数（全量枚举当前进程快照）。
- **处理逻辑**：
  1. 枚举进程快照（PID/PPID/名称/路径/创建时间/工作集/会话/签名方），并采集自启动来源（注册表 Run 键 / Windows 服务 / 计划任务 / 启动文件夹，四类）与活动信号（活跃网络连接、CPU 累计时间）；
  2. 判定✅推荐：a) 孤儿——父 PID 无对应存活进程，**或**父 PID 对应进程的创建时间晚于本进程（后者为 PID 复用，真父已退出）；b) 内置残留模式库命中（进程名/路径匹配 updater、update.exe、crashpad、crashreporter、setup 等，首版基线见附录）；c) 主程序已退出的子进程群——同可执行文件目录下、进程树根已退出而存活的子进程（典型：已关闭的浏览器/IDE 留下的 renderer、语言服务器）；d) 无可见顶层窗口 + 非服务 + 非系统目录的用户级应用；
  3. 判定⚠️谨慎：杀后会被拉起（来源为配置了失败恢复的 Windows 服务，或存在对应计划任务）；有活跃网络连接或显著 CPU 累计（疑似下载/同步中）；占用 <50MB（杀了没意义）；有托盘图标（疑似常驻使用中）；
  4. 判定🚫不推荐：内置系统保护名单（wininit/csrss/lsass/svchost/services/dwm 等 + 系统目录微软签名进程）；安全软件；有可见窗口（正在使用）；本工具自身；
  5. 冲突消解：多级依据同时命中时取最保守级（🚫 > ⚠️ > ✅；例：孤儿但占用 <50MB → ⚠️，孤儿且有托盘图标 → ⚠️）；均未命中任何依据的进程不进列表；白名单进程完全排除（不进任何级别，见 F4）后输出三级分类结果。
- **输出**：三级进程清单（含每项完整判定依据），供 F2 展示。
- **异常**：见 §3.7（扫描零推荐、进程集变化等）。

#### 功能 F2：推荐列表展示（对应 R02）
- **触发**：F1 扫描完成自动渲染。
- **输入**：F1 输出的三级清单。
- **处理逻辑**：按级分组（✅默认勾选 / ⚠️默认不勾可手动勾 / 🚫不可勾），组内按内存占用降序；行展开显示详情。
- **输出**：每项可见——主进程名与**进程树**（父子关系）、原因说明（对应 F1 判定依据的中文文案）、来源类型（自启动注册表/服务/计划任务/启动文件夹）、内存占用、"杀掉后是否会被拉起"提示。
- **异常**：见 §3.7（空状态）。

#### 功能 F3：一键释放（对应 R03）
- **触发**：底部"一键释放"按钮，作用于当前勾选项。
- **输入**：勾选的主进程集合（普通权限；清单中含需提权项时提供"以管理员身份重启"入口）。
- **处理逻辑**：
  1. 逐项校验存活（快照可能过期）；
  2. 以勾选项为根构建进程树，树内🚫保护名单节点及其子树跳过并记录；
  3. 对每棵树：先请求优雅关闭（窗口关闭消息）→ 等待 3 秒 → 仍存活则强制结束（TerminateProcess）；
  4. 汇总逐项结果（已释放/强制结束/已自行退出/需管理员/失败+原因）与**实际释放量（释放前后系统可用内存差）**。
- **输出**：结果报告（逐项 + 汇总释放量）；报告内提供"以管理员身份重启"入口——重启后自动重新扫描，上次标记"需管理员"的项自动恢复勾选，可直接再次一键释放；结果写入 F6 日志。
- **异常**：见 §3.7（竞态/权限/拦截/树保护/防重入）。

#### 功能 F4：白名单（对应 R04）
- **触发**：列表项右键 →"此进程永不推荐"。
- **输入**：进程名（按名称匹配，路径变化不影响）。
- **处理逻辑**：写入本地白名单文件（用户数据目录 JSON）；F1 扫描时完全排除（不进任何级别列表）。
- **输出**：主界面工具栏提供"白名单管理"面板，列出全部白名单进程名并支持逐项移除（已入单进程不出现在扫描列表，移除入口不依赖列表右键）；移除后重新扫描即恢复参与判定。
- **异常**：见 §3.7（文件损坏重建）。

#### 功能 F5：内存概览（对应 R05）
- **触发**：工具启动与每次扫描/释放后刷新。
- **输入**：系统内存性能计数器。
- **处理逻辑**：展示三类数值——物理内存占用率（In Use）、已提交内存（commit）、可用缓存（standby），并附口径说明：占用率仅反映 In Use，standby 属可回收缓存不计入占用率；高占用且无卡顿、commit 余量充足时未必是内存压力。
- **输出**：顶部概览条。
- **异常**：见 §3.7（计数器读取失败按无数据处理）。

#### 功能 F6：释放历史日志（对应 R06）
- **触发**：每次一键释放完成（含全部失败）自动追加。
- **输入**：F3 结果报告。
- **处理逻辑**：本地日志文件追加一行（JSONL：时间/进程清单/逐项结果/实际释放量）。
- **输出**：日志文件可外部打开查看；成功度量回溯依据（§1.3）。
- **异常**：见 §3.7（写失败不阻塞结果展示）。

| R02 | 扫描完成 | 展开任一推荐项详情 | 可见：主进程名、进程树（父子层级）、原因说明、来源类型、内存占用、是否会被拉起提示，六要素齐全 |
| R02 | 某进程来源为配置了失败恢复的 Windows 服务 | 查看该项 | 显示⚠️谨慎级文案"杀掉后会被服务管理器拉起，建议先禁用来源" |
| R03 | 勾选 1 个含 3 个子进程的主进程树 | 点击"一键释放" | 整树按"优雅关闭→3s→强杀"处理完毕；结果报告含逐项结果与实际释放量（MB）；任务管理器中该树进程不再存在 |
| R03 | 勾选项中含需管理员权限的进程 | 一键释放 | 该项标记"需管理员权限"未释放，其余正常释放；界面出现"以管理员身份重启"入口 |
| R03 | 待释放树内含保护名单进程（如 svchost 子节点） | 一键释放 | 保护节点及其子树被跳过，结果报告中列出跳过项与原因，其余正常释放 |
| R04 | 对某进程右键选择"此进程永不推荐" | 重新扫描 | 该进程不出现在任何级别列表（✅/⚠️/🚫 均无）；"白名单管理"面板中可见该项 |
| R04 | 白名单文件被人为损坏 | 启动工具 | 自动重建空白名单文件，工具正常启动不崩溃 |
| R05 | 工具启动完成 | 查看顶部概览条 | 显示占用率（In Use）、已提交内存（commit）、可用缓存（standby）三类数值，与任务管理器/资源监视器口径一致 |
| R06 | 完成一次一键释放（含部分失败） | 打开日志文件 | 该次记录含时间、进程清单、逐项结果（含失败原因）、实际释放量 |

### 3.3 数据结构 / 接口 / 页面交互（按需）
- **数据结构**：
  - 进程快照项：PID、PPID、名称、可执行路径、创建时间、工作集（MB）、会话、签名方、来源类型、分类（✅/⚠️/🚫）、判定原因列表、树关系；
  - 白名单文件：用户数据目录 JSON（进程名数组）；
  - 释放日志：用户数据目录 JSONL（每行一次释放：时间/进程清单/逐项结果/释放量）。
- **接口**：无网络接口，纯本地。进程枚举与 PPID 获取走 CreateToolhelp32Snapshot、创建时间走 GetProcessTimes、窗口枚举 EnumWindows、关闭消息 WM_CLOSE、内存数据走性能计数器——以上经 CsWin32 源生成器访问；如需 ntdll Native API（如 NtQueryInformationProcess），CsWin32 覆盖不全，允许手写 P/Invoke 例外（不纳入"经 CsWin32"统一口径）。
- **页面交互**：单主窗口 = 顶部概览条（R05）+ 中部三级分组列表（可展开行、多选复选框、内存排序）+ 底部操作栏（开始扫描/一键释放/结果摘要）+ 工具栏"白名单管理"面板（F4）；列表项右键菜单（加入白名单）；结果报告内"以管理员身份重启"入口（F3）；状态：空态（未扫描/零推荐）、扫描中（异步进度）、释放中（按钮禁用）。

### 3.4 非功能性需求
- **性能**：全量扫描 ≤3s（典型 300–600 进程）；扫描异步执行、UI 不冻结；整批释放 ≤30s（含每进程 3s 优雅等待）。
- **自身资源**：工具工作集 ≤100MB；不常驻、不轮询、不后台扫描（仅手动），关闭即零占用。
- **安全**：全程只读采集系统信息，不写注册表、不改系统配置（仅白名单与日志两个自有数据文件，均落用户数据目录）；保护名单进程任何情况下不可勾选；不对抗防软。
- **可用性**：释放动作幂等（进程已死计跳过不计失败）；崩溃不改变任何系统状态。
- **兼容性**：Windows 10 1809+ / Windows 11，x64。

### 3.5 约束与假设
- **技术约束**：C# / .NET 8 / WPF；Win32 API 优先经 CsWin32 源生成器访问（ntdll Native API 手写 P/Invoke 例外，见 §3.3）；单文件自包含便携 exe（v1 免安装）；**分层架构（扫描引擎/规则库/UI 严格分离）——商用预留核心措施，引擎与规则库不得依赖 UI**。
- **业务假设**：单用户桌面会话（非终端服务器多会话）；界面中文。若不成立（商用多环境）：需补兼容测试矩阵与多语言（v2）。
- **依赖**：无外部服务与网络依赖，运行时纯本地。
