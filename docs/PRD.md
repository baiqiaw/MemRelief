## 第1层 · 决策层（Why & What）

### 1.1 需求本质
- **用户要完成的任务 / 要解决的问题**（一句话）：识别并安全结束占用内存的孤儿进程与无用应用，缓解慢性卡顿与偶发内存耗尽，且每个"杀/不杀"决策都有可读的理由。
- **不做的后果**：用户继续在任务管理器里凭进程名猜测哪些能杀——误杀风险与漏杀并存，90%+ 占用与卡顿/爆发长期存在。

### 1.2 证据（防伪需求，强制带来源）
- **用户原话**："我的电脑经常性内存使用90%以上，里面有大量的孤儿进程遗留，有大量我平时没用上的应用占着内存，我需要一个工具来清理并释放这些进程及所占内存；我需要的功能有：推荐可以释放的进程及内存，说明原因，主进程是谁等关键信息；不推荐的释放也需要说明，然后我可以多选进行一键释放；另外从网络搜索最佳实践。"（来源：2026-09-05 prd-writer 拷问会话原始输入，逐字引用；末句"从网络搜索最佳实践"界定为**开发期调研输入**——已执行，见下方调研结论与附录，产品自身不含联网功能）
- **体验确认**：内存 90%+ 时的实际体验为"慢性卡顿（切换慢/转圈）+ 偶发爆发（应用崩溃/提示内存不足）"混合（来源：拷问问题 1，用户选 D）。
- **本机基线（已采样 2026-09-05 13:58，高压时点）**：物理 15.73 GB，In Use 97.7%，standby 仅 0.3 GB（缓存已挤干），commit 30.49/38.73 GB（78.7%），硬缺页 PagesInput/sec = 1102（上升趋势，卡顿直接成因）；孤儿 11 个 + 残留 3 个，**聚合私有提交 1673 MB**（≥500MB 建议判据 3 倍，假设验证通过）。采样明细与脚本：scripts/baseline-result.txt、scripts/baseline-sample.ps1。
- **最佳实践调研**（2026-09-05，链接见附录）：① 任务管理器占用率仅反映 In Use；standby/cache 属可回收缓存（计入"可用"而非"已使用"），不抬高占用率——高占用率不必然是问题，真压力信号是持续高占用+卡顿+commit 接近上限；② 传统内存优化器（EmptyWorkingSet 工作集修剪）被主流开发者共识视为无效（页面移入 standby 后软缺页弹回，还付性能代价），**真正释放内存的唯一有效手段是结束进程**；③ 孤儿进程检测以父 PID 存活判定为成熟方法；Windows 复用 PID，需以创建时间校正——父 PID 对应进程的创建时间**晚于**子进程时，恰证明真父已退出（存活者为 PID 复用者），应判孤儿；④ Windows 不做 reparent——explorer 崩溃重启、安装器退出后，其启动的正常应用 PPID 均指向死进程，孤儿判定须叠加旁证抑制误报（见 §3.1 F1 旁证条件）。

### 1.3 业务目标与成功度量
- **业务目标**：从"经常性 90%+ 占用、慢性卡顿 + 偶发内存耗尽" → "一键清理后占用可观测下降、爆发频率下降、✅级默认勾选路径两步完成（扫描→确认释放）"。
- **成功度量（可验证）**：
  1. **释放量（主数值）**：每次一键释放报告"逐进程私有提交内存合计"（快照持有、可归因），并留痕日志（R03/R06）；
  2. **占用率变化**：日志记录释放前/后 In Use 与 commit 快照（R06 字段），清理效果可回溯对比；不预设死数（下降量取决于当时进程构成），以本机基线（附录待确认 #2）为 baseline；
  3. **爆发频率**：主观体验为主，日志辅证（清理时间线与用户回忆的爆发事件人工关联；v1 无遥测，商用版升级）。

### 1.4 目标用户与场景
- **目标用户**：本人（Windows 11 x64，开发者）。v1 纯自用；架构上以分层设计为商用预留（见 §3.5）。
- **典型场景**：
  1. **日常清理**：感觉系统变卡 → 打开工具 → 扫描 → 读推荐与原因 → 勾选 → 确认释放（频率：每日~隔日）；
  2. **爆发应急**：应用提示内存不足/浏览器标签被杀 → 立即打开工具清理（频率：每周数次；**预期边界**：爆发时占用大头若为正在使用的应用（如浏览器），本工具不解决——该场景应先关闭在用大应用）；
  3. **来源体检**：查看哪些进程来自自启动/服务/计划任务（含具体条目名，经搜索框定位）→ 按来源类型到对应系统工具禁用（启动应用→任务管理器；服务→services.msc；计划任务→taskschd.msc；启动文件夹→删除 shell:startup 快捷方式），治本（频率：每周）。
- **用户旅程**：感知卡顿/爆发（痛点：不知道哪些进程能杀）→ 打开工具扫描（痛点：任务管理器无推荐无解释）→ 读推荐+原因+进程树（解决：决策辅助）→ 多选勾选 → 确认并一键释放（可取消）→ 查看实际释放量验证（解决：效果可观测）。

### 1.5 范围与优先级
- **P0（必须做，= MVP 边界）**：扫描引擎与三级推荐（R01）、推荐列表信息展示（R02）、一键释放（R03）、白名单（R04）。
- **P1（辅助）**：内存概览条（R05）、释放历史日志（R06）。
- **不做（边界，v1 明确排除）**：
  - 自动/定时清理、托盘常驻、工具自身开机自启——误杀风险与"仅手动按需清理"定位冲突（拷问问题 4）；
  - 自启动项禁用**操作**——写系统配置风险大，信息层展示已打通治本路径（拷问问题 5）；
  - 安装包/代码签名/自动更新/遥测/多语言——归 v2 商用化；
  - 自定义规则编辑器——v1 只留白名单，模式库/常驻名单/安全软件名单随使用迭代（拷问问题 7）；
  - 工作集修剪类"内存优化"——调研证明无效（附录），不做；
  - 托盘图标真实枚举（UIA 通知区遍历）——无公开 API、可靠性差、成本不可控，v1 以"常驻应用名单"替代该信号（§3.1 口径表 #5），UIA 方案归 v2 评估；
  - ⚠️级正向勾选记忆（"这项我总杀"）——v2 候选；
  - 强制结束🚫级进程的"自担风险"出口——安全边界，v1 不提供。

## 第2层 · 方案层（How）

### 2.1 方案对比与选择
- **核心方案对比：怎么"释放内存"**
  - 方案 A：传统内存优化器（EmptyWorkingSet 修剪各进程工作集） | 优点：实现简单、数字立刻变好看 | 缺点：**无效**——页面移入 standby 后软缺页弹回，还付性能代价；开发者共识视之为安慰剂 | 成本：低
  - 方案 B：进程识别 + 结束进程（推荐引擎 + 树状两段式释放） | 优点：唯一真正释放内存的路径；契合"孤儿/无用应用"的实际病因 | 缺点：推荐准确性依赖规则工程质量 | 成本：中
  - **推荐**：B | **理由**：调研结论（附录）证明 A 类工具无效；用户的痛点构成（孤儿+无用应用）恰好是 B 的能力面。
- **自建 vs 既有手段对比**
  - Process Explorer（进程树+父子关系现成）+ Autoruns（来源治理现成）+ 物理加内存：能力覆盖大半，零开发成本；
  - 自建：不能自动推荐"哪些能杀"（Process Explorer 只展示关系不判断）、无中文场景化解释、无释放量归因；
  - **决策**：自建——理由是商用预留（可分发的产品而非个人脚本组合）+ 推荐引擎（规则+解释+分级）是现有工具没有的核心价值；练手为次要从属理由。此决策为显式记录，v2 立项时可复查。
- **技术栈对比**
  - 方案 A：Python + PySide6 + psutil | 优点：进程枚举开发最快、本机 Python 已装 | 缺点：PyInstaller 打包是杀软误报重灾区（系统工具被 AV 误杀 = 商用口碑灾难）；PySide6 LGPL 商用尽调问号；自身占用大 | 成本：开发低、商用迁移高
  - 方案 B：C# + WPF + .NET 8 + CsWin32 | 优点：单文件自包含发布、签名/安装包/自动更新生态成熟、WPF/.NET MIT 零授权歧义、原生占用小；本机 .NET SDK 8/9/10 已装（实测 2026-09-05） | 缺点：Win32 访问管道略多 | 成本：开发中、商用迁移零
  - **推荐**：B | **理由**：用户明确"为后续商用做准备"（拷问问题 9 追加前提）；商用最大成本在分发与信任面，正是 B 的长板；避免商用前整轮重写。
- **权限方案对比**：每次管理员启动（UAC 烦扰）vs **默认普通权限 + 按需"以管理员身份重启"**（推荐，主流做法）vs 单次碎片化提权（体验差）。推荐理由：主场景（用户级孤儿/残留）普通权限已覆盖。

## 第3层 · 实现层（Detail）

### 适用性声明
> 【v2】声明下方条件性产物的适用性，供 prd_check #9 校验（v2 必填）。**异常处理表近普适、默认必备，不在本声明内**；仅状态流转/埋点按需求性质判定。

- 埋点方案：不适用（v1 纯本地自用无遥测，成功度量以 R06 本地日志与主观体验可观测；商用遥测归 v2，见 §1.5 不做边界）

### 3.1 功能详细设计（逐功能）
#### 功能 F1：扫描引擎与三级推荐（对应 R01）
- **触发**：主界面"开始扫描"按钮；普通权限即可（提权项见 F3）。
- **输入**：无参数（全量枚举当前进程快照）。
- **处理逻辑**：
  1. 枚举进程快照（PID/PPID/名称/路径/创建时间/**私有提交内存**/签名方/命令行），并采集自启动来源（**含具体条目名**，四类采集范围见口径表 #12）与活动信号（网络连接/CPU 差分，见口径表 #6/#7）；
  2. 判定✅推荐：a) 孤儿——父 PID 无对应存活进程，**或**父 PID 对应进程的创建时间晚于本进程（后者为 PID 复用，真父已退出）；**旁证降级**：同可执行文件目录下存在其他存活进程 → 降⚠️（"同目录存在存活进程，疑似在用组件"——抑制 explorer 崩溃误报与 crashpad 类 by-design 孤儿）；b) 内置残留模式库命中（进程名/路径匹配 updater、update.exe、crashpad、crashreporter、setup 等，首版基线见附录）；c)（v1.1 并入 a)：原"主程序已退出的子进程群"不再作为独立依据——其场景由 a) 孤儿判定 + 旁证降级覆盖；d) 无可见顶层窗口 + 非服务 + 非系统目录的用户级应用（窗口口径见口径表 #4，含 UWP 特例）；
  3. 判定⚠️谨慎：杀后会被拉起（来源为配置了失败恢复的 Windows 服务，或存在对应计划任务）；有活跃网络连接（ESTABLISHED）或扫描窗口内 CPU 差分显著（疑似下载/同步/任务进行中）；进程树合计私有提交 <50MB（**孤儿与模式库命中豁免此降级**——小体量残留批量清理正是高频场景）；进程名命中内置常驻应用名单（微信/网盘/下载器等，托盘信号的替代口径，见口径表 #5）；
  4. 判定🚫不推荐：内置系统保护名单（wininit/csrss/lsass/svchost/services/dwm 等 + 系统目录微软签名进程 + OpenProcess 受拒的 PPL 进程）；安全软件（口径表 #11）；有可见窗口（正在使用）；本工具自身；
  5. 冲突消解：多级依据同时命中时取最保守级（🚫 > ⚠️ > ✅；例：孤儿且有 ESTABLISHED 连接 → ⚠️）；**服务进程（未配置失败恢复者）归🚫级**，原因"服务进程——建议经 services.msc 禁用来源后重启"（保守不提供勾选，且保留"不推荐也说明"原则；工具型服务有窗口者本就归🚫）；均未命中任何依据的进程不进列表（可经 F2 搜索框查询）；白名单进程完全排除（不进任何级别，见 F4）后输出三级分类结果。

- **判定信号技术口径表**（S0-1；研发据此可直接估时，逐信号：数据源 × 过滤口径 × 失败兜底）：

  | # | 信号 | 数据源 | 过滤/判定口径 | 采集失败兜底 |
  |---|------|--------|--------------|------------|
  | 1 | 父进程存活/PID 复用 | CreateToolhelp32Snapshot 全量（PID/PPID）+ GetProcessTimes（创建时间） | PPID 无对应进程 → 孤儿；PPID 对应进程创建时间晚于本进程 → 孤儿（复用） | 创建时间不可读 → 不进✅级 |
  | 2 | 残留模式库 | 进程名+可执行路径子串匹配（附录基线清单） | 不区分大小写 | 纯本地匹配，无失败路径 |
  | 3 | 旁证（同目录存活） | 口径 #1 快照 + 可执行文件目录分组（比较前归一化：大小写不敏感 + 8.3 短名展开） | 同可执行目录存在其他存活进程 → ✅降⚠️；**同目录存活进程本身为孤儿判定命中者不计为旁证（孤儿群互不为旁证，避免残留群整群降级）** | 路径不可读 → 不进✅级 |
  | 4 | 可见窗口 | EnumWindows 顶层窗口 + GetWindowThreadProcessId 归属 + DwmGetWindowAttribute(DWMWA_CLOAKED) | 计入：WS_VISIBLE、非 WS_EX_TOOLWINDOW、非 cloaked、属主=目标进程；**UWP 特例**：路径在 WindowsApps 的 UWP 包进程（微软与第三方一律，窗口属 ApplicationFrameHost 自身枚举不到）→ 不适用本判定，保守归⚠️ | 枚举失败 → 视为有窗口（保守归🚫/⚠️） |
  | 5 | 常驻应用（托盘替代） | 内置常驻应用名单（**进程名精确匹配**，随模式库同机制维护，见附录） | 名单精确命中 → ⚠️"疑似常驻应用"（v1 不做托盘 UIA 枚举，见 §1.5） | 名单为本地资源，无失败路径 |
  | 6 | 活跃网络连接 | GetExtendedTcpTable 按 PID 关联（UDP 无连接语义，不采集） | 仅 ESTABLISHED 状态 TCP 计"活跃"；LISTEN/TIME_WAIT 不计 | 取表失败 → 不进✅级 |
  | 7 | CPU 活动 | 扫描开始/结束两次采样进程 CPU 时间（GetProcessTimes），差分（以 ≤3s 扫描窗口为前提） | 差分 > 1s CPU 时间 → "疑似任务进行中" | 不可读 → 不进✅级 |
  | 8 | 服务失败恢复 | OpenSCManager + EnumServicesStatusEx（SERVICE_STATUS_PROCESS.dwProcessId 建立进程↔服务关联）+ **QueryServiceConfig2(SERVICE_CONFIG_FAILURE_ACTIONS)** | 服务进程且失败恢复动作含 SC_ACTION_RESTART → ⚠️会被拉起 | 查询失败 → 不进✅级 |
  | 9 | 签名验证 | WinVerifyTrust，**仅对候选推荐进程执行**（%windir% 系核心目录命中者直接按微软处理，不验签）；结果按"路径+mtime"缓存 | 验签四分支：微软 → 🚫候选；有效非微软 → 正常参与分级；无效/无签名 → 不额外降级（正常参与） | Access Denied/验不了 → 按受保护处理（🚫/不进✅） |
  | 10 | 系统目录 | 清单枚举（环境变量解析 + Known Folder API）：%windir%、System32、SysWOW64、WinSxS；**Program Files\WindowsApps 仅用于 #4 UWP 识别，不触发"系统目录→按微软处理→🚫"链路**（否则与 UWP ⚠️ 特例矛盾） | 路径命中清单 → "系统目录" | 解析失败 → 视为系统目录（保守） |
  | 11 | 安全软件 | 双通道：内置厂商进程名单（附录维护）+ 签名方匹配；PPL/句柄受拒进程视为受保护 | 任一通道命中 → 🚫 | OpenProcess 受拒即视为受保护（保守🚫） |
  | 12 | 来源采集（含条目名） | Run 键：HKLM\…\Run 读 64 位 + 32 位两视图（KEY_WOW64_32KEY 访问，不硬编码 Wow6432Node 路径）；HKCU\…\Run 单视图（WOW64 共享键不重定向）；StartupApproved 读禁用态；服务：同 #8（条目名=服务名）；计划任务：ITaskService COM（**单列技术通道，不在 CsWin32 口径内**，仅采集根与用户自定义文件夹，\Microsoft\Windows 内建任务不采集）；启动文件夹：用户+公共两处 | 可执行路径**精确匹配**（不按进程名匹配，避免误配）→ 来源类型+条目名 | 单类采集失败 → 来源显示"采集失败"，该进程不进✅级 |
  | 13 | 内存占用 | 快照字段：**私有提交内存**（GetProcessMemoryInfo 的 PrivateUsage；工作集会被系统修剪失真，不采用） | ⚠️阈值按**进程树合计**判定（树边界 = 该进程的全部后代进程） | 不可读 → 0（不触发小体量降级） |
  | 14 | 白名单 | 白名单文件（名称匹配，v1） | 命中 → 完全排除 | 文件损坏 → 重建并备份（见 §3.7） |
  | 15 | 计划任务拉起 | 复用 #12 的 ITaskService 采集（任务动作的可执行路径） | 任务触发器为"登录时/启动时/周期"且动作指向该进程可执行路径 → ⚠️会被拉起 | 采集失败 → 不进✅级 |

- **保守兜底总则**：任一保护性判定所需字段（路径/创建时间/签名/连接表/CPU）采集失败 → **该进程不得进入✅级**（宁可漏推荐，不可误推荐）。
- **权限×数据可见性矩阵**：

  | 能力 | 普通权限 | 管理员（以管理员重启后） |
  |------|---------|------------------------|
  | 枚举进程 | 全部可见（名称/PID/内存） | 同左 |
  | 读路径/命令行/签名 | 当前用户进程可读；提权进程/PPL 受拒（兜底总则生效） | 全部可读（PPL 除外） |
  | 结束进程 | 当前用户进程 | + 其他用户进程/服务进程 |
  | 不可见/不可杀 | 无（受拒进程以兜底总则处理） | PPL 进程（如实报"受保护"） |

- **输出**：三级进程清单（含每项完整判定依据），供 F2 展示。
- **异常**：见 §3.7（扫描零推荐、扫描失败、进程集变化等）。

#### 功能 F2：推荐列表展示（对应 R01/R02）
- **触发**：F1 扫描完成自动渲染。
- **输入**：F1 输出的三级清单。
- **处理逻辑**：按级分组（✅默认勾选 / ⚠️默认不勾可手动勾 / 🚫不可勾且**默认折叠仅显示计数**，可展开），组内按进程树合计私有提交降序；行展开显示详情；列表上方提供**搜索框**——可按进程名/PID 查询**全量快照**中任意进程的判定结果与依据（含"未命中规则，不进列表"/"白名单排除"两种不可见原因），消除列表外黑箱。
- **输出**：每项可见——主进程名与**进程树**（父子层级；孤儿显示"(父进程已退出)"）、原因说明（对应判定依据的中文文案）、来源类型与**具体条目名**（无四类来源时显示"无（手动启动）"）、进程树合计内存占用、"杀掉后是否会被拉起"提示；白名单排除的进程在列表尾部折叠区显示计数（可见但不占焦点）。
- **异常**：见 §3.7（空状态）。

#### 功能 F3：一键释放（对应 R03）
- **触发**：底部"一键释放"按钮，作用于当前勾选项。
- **输入**：勾选的主进程集合（普通权限；清单中含需提权项时提供"以管理员身份重启"入口）。
- **处理逻辑**：
  1. **确认弹窗**（轻量、单次）：显示"将结束 N 个进程树 / 合计约 X MB 私有提交内存"，确认后进入释放（防误触最后防线）；
  2. 逐项校验存活**与身份一致性**（进程名+创建时间与快照一致；不一致 → 该项标记"进程已变化，已跳过"不执行——防扫描后放置期间 PID 被复用为新进程而杀错对象）；
  3. 以勾选项为根构建进程树，树内🚫保护名单节点与**白名单节点**及其子树均跳过并记录；
  4. **多树并行**处理，每棵树：先请求优雅关闭（WM_CLOSE）→ 等待 3 秒 → 仍存活则强制结束（TerminateProcess）；**已判定无可见窗口的进程跳过优雅阶段直接强杀**（无消息循环，等待无意义）；
  5. 释放过程中提供**取消**（跳过所有未开始的树，进行中的树等待完成），释放中关闭主窗口 = 取消并等待当前树收尾；
  6. 汇总逐项结果与释放量。**释放量口径（主释放量）= 被结束进程的私有提交内存（快照持有）合计**——可归因、不受系统噪声污染；**校验释放量 = 系统 commit 前后差**（可能为负或失真，如实显示并附一句口径说明）；
  7. **结果分类映射**：底层同为 Access Denied 的失败按"目标进程所有者/令牌类型"区分——非当前用户或服务或 PPL → "需管理员权限"；当前用户且非服务仍失败 → "被拦截（附系统错误码）"。
- **输出**：结果报告（逐项 + 主释放量/校验释放量双数值；跳过项说明"其子进程将于下次扫描重新评估"；报告内提供"以管理员身份重启"入口——重启后自动重新扫描，上次"需管理员"失败类项（按名称+可执行路径识别）在列表中**高亮标记，由用户重新勾选**后再次一键释放——不自动恢复勾选、状态不落盘；扫描阶段即按口径 #8 服务判定与跨用户进程**预标"需管理员"**）；**释放完成后自动移除已结束项**并提示"可重新扫描"；被拉起类（⚠️服务恢复）项在报告中附"该进程可能被服务管理器重新拉起，建议先禁用来源"预期提示；结果写入 F6 日志。
- **异常**：见 §3.7（身份变化/竞态/权限/拦截/树保护/防重入等）。

#### 功能 F4：白名单（对应 R04）
- **触发**：列表项右键 →"此进程永不推荐"（**仅✅/⚠️级项可加入**；🚫保护名单进程不可加白——无意义且制造绕过保护歧义）。
- **输入**：进程名 + 记录性元数据（添加时间/当时可执行路径/备注，默认空）。
- **处理逻辑**：写入本地白名单文件（用户数据目录 JSON，条目结构 `{名称, 添加时间, 路径, 备注}`）；F1 扫描时完全排除（不进任何级别列表）；**F3 树状释放时白名单节点与保护名单同优先级跳过**（"永不推荐"心智不可被树释放穿透）；匹配粒度为进程名（v1）——同名不同路径进程一并排除为**已知边界**（记录于附录），v2 评估"名称+签名方"粒度。
- **输出**：主界面工具栏"白名单管理"面板，列出全部条目（含元数据）并支持逐项移除；移除后重新扫描即恢复参与判定；F2 列表尾部折叠区显示"因白名单排除 N 项"计数。
- **异常**：见 §3.7（文件损坏备份重建）。

#### 功能 F5：内存概览（对应 R05）
- **触发**：工具启动与每次扫描/释放后刷新。
- **输入**：系统内存状态（数据源：**优先 NtQuerySystemInformation 系统内存性能信息**（与任务管理器同源；§3.3 已开的 ntdll 例外通道）；**PDH 兜底**（Standby Cache Reserve/Normal Priority/Core 三计数器相加近似 standby）；实测两通道后定稿，standby 不可得时 R05 降级为两数值并注记）。
- **处理逻辑**：展示三类数值——物理内存占用率（In Use）、已提交内存（commit）、可用缓存（standby），并附口径说明：占用率仅反映 In Use，standby 属可回收缓存不计入占用率；高占用且无卡顿、commit 余量充足时未必是内存压力。
- **输出**：顶部概览条。
- **异常**：见 §3.7（计数器读取失败）。

#### 功能 F6：释放历史日志（对应 R06）
- **触发**：每次一键释放完成（含全部失败）自动追加。
- **输入**：F3 结果报告。
- **处理逻辑**：本地日志文件追加一行（JSONL，字段级 schema：`{时间(本地时区 ISO8601 含毫秒), 释放前快照{InUse, commit}, 释放后快照{InUse, commit}, 进程清单[{PID, 名称, 可执行路径, 命令行, 结果, 原因}], 主释放量(私有提交合计), 校验释放量(commit 差)}`；取消收尾的释放记已执行部分，"原因"=该项释放/跳过原因含失败原因）；**轮转策略：单文件上限 5MB，保留最近 3 个滚动副本**；工具栏提供"打开日志/打开数据目录"入口。
- **输出**：日志文件；§1.3 度量 1/2/3 的回溯依据。
- **异常**：见 §3.7（写失败/日志损坏）。

### 3.2 验收标准（强制可验证，Given-When-Then）
> 每个 active 需求/功能必须有 ≥1 条 GWT 验收。下游 issue/验收照此展开。ID 与第 0 层清单一一对应（覆盖一致）。
> 前置构造规格：孤儿测试进程须同时满足——父退出、进程树合计私有提交 >50MB（测试程序申请内存构造）、无可见窗口、无 ESTABLISHED 连接、非服务、非 UWP、不在常驻名单、同可执行目录无其他存活进程（避开全部降级信号）。

| ID | Given（前置） | When（操作） | Then（可观测结果） |
|----|--------------|-------------|-------------------|
| R01 | 按"前置构造规格"存在 1 个孤儿测试进程（测试程序对构造） | 点击"开始扫描" | ≤3s 完成扫描（计时口径：点击→列表渲染完成，进程数 300-600）；该进程出现在✅推荐级，原因含"孤儿进程（父进程已退出）" |

| R01 | 存在命中残留模式库的进程（如 xxxupdater.exe）且同目录无存活主程序、树合计 <50MB（豁免验证） | 扫描 | 出现在✅推荐级（模式库命中豁免小体量降级），默认勾选 |
| R01 | 存在无可见窗口的用户级应用且满足前置构造规格（无 ESTABLISHED 连接、非常驻名单、树合计 >50MB） | 扫描 | 出现在✅推荐级，原因"无窗口用户级应用" |

### 3.3 数据结构 / 接口 / 页面交互（按需）
- **数据结构**：
  - 进程快照项：PID、PPID、名称、可执行路径、创建时间、**私有提交内存（MB，树合计另算）**、签名方、命令行、来源类型与条目名（多值，四类枚举+无）、分类（✅/⚠️/🚫/未命中）、判定原因列表、树关系；
  - 白名单文件：用户数据目录 JSON，条目 `{名称, 添加时间, 路径, 备注}` 数组；
  - 释放日志：用户数据目录 JSONL（字段级 schema 见 F6），5MB×3 副本轮转；
  - 提权恢复状态：随"以管理员身份重启"的进程启动参数携带（不落盘）。
- **接口**：无网络接口，纯本地。进程枚举与 PPID 走 CreateToolhelp32Snapshot、创建时间/CPU 走 GetProcessTimes、窗口枚举 EnumWindows + DWM cloaked 检测、关闭消息 WM_CLOSE、网络 GetExtendedTcpTable、内存占用 GetProcessMemoryInfo(PrivateUsage)、服务 OpenSCManager 系（含 QueryServiceConfig2）、签名 WinVerifyTrust（仅候选+缓存）——以上经 CsWin32 源生成器访问；**两类例外走手写通道，不入"经 CsWin32"口径**：①计划任务 ITaskService（COM）；②standby 等系统内存信息（NtQuerySystemInformation）。
- **页面交互**：单主窗口 = 顶部概览条（R05）+ 搜索框（全量判定查询）+ 中部三级分组列表（✅/⚠️ 可勾选，🚫 默认折叠仅计数；可展开行、树合计内存排序）+ 底部操作栏（开始扫描/一键释放/结果摘要）+ 工具栏"白名单管理"面板与"打开日志/数据目录"入口；列表项右键菜单（✅/⚠️级可加入白名单）；确认弹窗（释放前）与结果报告（非模态面板，含"以管理员身份重启"入口）；状态机见 §3.6。

### 3.4 非功能性需求
- **性能**：全量扫描 ≤3s（测量口径：点击"开始扫描"→列表渲染完成；典型负载 300–600 进程；含来源采集与候选验签（缓存生效后）；极端高内存压力场景不承诺，如实反映耗时）；扫描异步执行、UI 不冻结；**释放并行口径：多树并行，单树 ≤5s（含 3s 优雅等待），整批 ≤30s**。
- **自身资源**：工具工作集 ≤100MB（测量条件：WPF 空载基线 + 一次 600 进程扫描后的峰值；.NET 8 WPF 基线约 60–120MB 随 GPU 驱动/运行时配置浮动，贴边运行，超标时先实测归因再决定优化或修订指标）；不常驻、不轮询、不后台扫描（仅手动），关闭即零占用。
- **安全**：全程只读采集系统信息，不写注册表、不改系统配置（仅白名单与日志两个自有数据文件，均落用户数据目录；提权重启后仍锚定同一用户数据目录）；保护名单进程任何情况下不可勾选；不对抗防软。
- **可用性**：释放动作幂等（进程已死计跳过不计失败）；崩溃不改变任何系统状态。
- **兼容性**：**v1 实测范围：Windows 11 x64（用户本机）**；Windows 10 1809+ 为商用目标面，v1 不承诺不验证（归 v2 商用化测试矩阵）。

### 3.5 约束与假设
- **技术约束**：C# / .NET 8 / WPF；Win32 API 优先经 CsWin32 源生成器访问（两类手写例外见 §3.3）；单文件自包含便携 exe（v1 免安装；数据落用户数据目录——便携换机时白名单/日志不随行，为已接受取舍）；**分层架构（扫描引擎/规则库/UI 严格分离）——商用预留核心措施，引擎与规则库不得依赖 UI**。
- **业务假设**：单用户桌面会话（非终端服务器多会话）；界面中文；孤儿+残留进程为本机内存压力主要来源之一（**M1 前置基线采样验证，见附录 #2**）。若不成立：重估立项方向；商用多环境需补兼容矩阵与多语言（v2）。
- **依赖**：无外部服务与网络依赖，运行时纯本地。
